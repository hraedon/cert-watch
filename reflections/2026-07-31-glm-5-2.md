## On the project

cert-watch is in good shape. The codebase is mature, security-conscious, and well-tested. The architecture decisions documented in AGENTS.md (SQL-paginated dashboard, SSRF hardening, CSP nonces, HMAC sessions, failure-isolation in scheduler) are sound and well-implemented. The maintenance-mode posture is appropriate — the project does what it needs to do and the test estate is the safety net.

The biggest structural debt is the 277 intra-function lazy imports. They're a pervasive convention rooted in a real problem (circular module dependencies between scan/alerts/database/events/policy), but the scale has grown far beyond the original rationale. The fix is a shared `types.py` leaf module that breaks the cycle for ~40% of them — but that's a medium-risk change that needs its own focused session, not a maintenance-mode quick fix.

The `dict[str, Any]` row-dict pattern (322 sites) is the second-largest debt. BC-031 intentionally avoids `sqlite3.Row` leaking into routes, but `TypedDict` would be the upgrade path. Again — high effort, low urgency for a maintenance-mode project.

## On the work done

The parallel subagent approach worked well for independent changes. Wave 1 (test fixtures, database exports, scan.py refactor) ran 3 agents in parallel with zero conflicts. Wave 2 (SQL helpers, bare-except logging, SchedulerContext) also ran cleanly. Wave 3 (views.py split) was correctly serialized after Wave 2 because it depended on the SQL helper extraction.

What went well:
- The `DeferredPostCommit` dataclass is a clean win — it eliminated `typing.cast` and made the deferred payload self-documenting with zero behavior change
- The `SchedulerContext` extraction turned 7 closures + 2 `nonlocal` mutations into a testable dataclass — this was the highest-complexity change and it went smoothly
- The views.py split was mechanical but high-impact — the 7 new modules are each focused and readable

What I'd want a second pair of eyes on:
- The `SchedulerContext._store_with_lock` method uses `self._deferred_post_commit` as an instance-level list that's reset at the start of each `scan_all()` call. This preserves the original closure behavior (the list was shared between `_scan_all` and its inner `_store_with_lock`), but it's a subtle coupling — if `scan_all()` is ever called concurrently on the same instance, the list would be corrupted. The original closure had the same issue (the list was captured by the inner closure), so this is not a regression — but it's worth noting.
- Three lazy imports had to stay in the new route modules because tests monkeypatch module attributes (`check_caa`, `process_pending`, `_scheduler_thread`). Moving them to top-level would break the monkeypatch path. This is correct but worth documenting — the test pattern is load-bearing for the import strategy.

What I'm confident in:
- The test fixture deduplication is pure mechanical cleanup — no behavior change
- The `database/__init__.py` cleanup is declarative-only (no runtime effect)
- The SQL helper extraction (`count_leaf_certs`, `team_dashboard_data`) is behavior-preserving — the same queries run, just from a different location

## Gaps to flag

- **`SchedulerContext` concurrent-call safety**: `_deferred_post_commit` is an instance attribute reset per `scan_all()` call. If `scan_all()` is called concurrently on the same instance (shouldn't happen — single scheduler thread), the list would be corrupted. The original closure had the same issue, so this is not a regression. `scheduler_context.py:scan_all()`.
- **Three lazy imports are load-bearing for test monkeypatching**: `check_caa` in `scan_history.py`, `process_pending` in `dashboard.py`, `_scheduler_thread` in `health.py`. Moving these to top-level would break tests. This is a test-design constraint, not a code smell — but it means the "move lazy imports to top-level" refactoring goal has exceptions.
- **`test_weekly_digest_guard.py`** is still a theater test — it replicates the digest algorithm and tests the replica. Now that `SchedulerContext.maybe_run_weekly_digest()` exists as a testable method, this test should be rewritten to call the real method. Low urgency.
- **AGENTS.md is stale on `importlib.reload`**: it claims "~8 individual test files still use inline `importlib.reload`" but zero actual usages remain. The cleanup is complete. This is a doc-truth-keeping issue per the maintenance contract.
- **E2E suite not run locally** — the route split is URL-transparent but CI's e2e + visual jobs are the real gate. Watch for `e2e.yml` failures on push.
