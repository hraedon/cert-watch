# UI inventory report (exploration, 2026-08-12)

15 page templates + 3 macro files; tokens.css (1277 lines) is the only CSS;
**no JS files in static/** — all script is inline `<script nonce>` blocks.

## Global chrome (base.html, 287 lines)

Topbar: wordmark+version → 7-item flat nav → spacer → user/logout → theme
toggle → `topbar_actions` (used only by dashboard for "Add host").
Nav: Dashboard `/`, Alerts `/alerts`, Scan history `/scan-history`, Insights
`/insights`, Team `/team` (if auth_user), Audit log `/audit`, Settings
`/settings` (if is_admin). **Not in nav:** `/reports/compliance`,
`/readiness`, `/crypto` — all set `active_page="insights"` and are reachable
ONLY from a link row inside insights.html's page header.

Below nav: error flash → warning flash → health banner (polls /api/health,
30s→300s backoff, visibility pause) → autogenerated-admin-password banner.

**The data-action registry**: a delegated click listener in base.html maps 18
`data-action` values to page-defined globals guarded by `typeof fn ===
'function'` — toggle-pivot-group, toggle-group, open-link, open-slide,
close-slide, switch-tab, click-target, stop-propagation, toggle-notes,
save-notes, toggle-owner, save-owner, test-ldap, test-smtp,
dismiss-autogenerated, check-revocation, toggle-host-notes, save-host-notes,
print. Plus delegated change (toggle-provider), submit (.confirm-form), and
keydown (Enter/Space for [data-action][tabindex]).

## Pages

1. **Dashboard** `/` (dashboard.html, 894 lines; params q, urgency, source,
   sort_by, sort_order, page, grouped, view). Head: h1 + fleet-grade widget +
   JS-string-built "Reports ▾" dropdown (CSV/JSON exports). 5-cell stat strip
   whose cells ARE the urgency filter links (disabled when a pivot view
   active). Toolbar: search + datalist of tags + 4-button segmented
   `view` control (All/By issuer/By owner/By method). TWO mutually exclusive
   tables: pivot table (expandable, lazy `fetch /api/pivot/...`) and inventory
   table (fingerprint-grouped expandable rows, chips for renewal/owner/notes/
   SANs/source/6-state chain status, expiry mini-bar, posture grade letter).
   Two empty-state variants. Pagination. **Then trust anchors** (upload form +
   table + delete) below pagination. Slide-over (3 tabs: scan host / upload /
   bulk CSV) with focus trap. Inline note editing via JS-injected form →
   `PATCH /api/hosts/{id}/notes`. capChips() DOM post-processing.
2. **Certificate detail** `/certificates/{cert_id}` (667 lines). Breadcrumb,
   header (CN + urgency pill + grade + chain chip; scan/download/delete).
   Left: operational summary (owner/renewal/runbook; inline edit) + host
   notes editor + security posture findings + "Check revocation" fetch +
   validity meter + SANs + renewal history + cert details grid + drift +
   tags (`<details>` editor) + cert notes editor. Right: chain timeline +
   5-state banner. THREE near-identical toggle/save function pairs.
3. **Host detail** — SAME URL `/certificates/{id}` renders host_detail.html
   (222 lines) when id is a certless host (routes/certificates.py:56-99).
   Duplicates the owner-edit panel (4th copy of toggleOwner). No host list
   page exists anywhere.
4. **Alerts** `/alerts` (159 lines). Segmented anchor filter WITH counts using
   `.cw-segmented` system used by NO other page. Alert cards (severity rail,
   NEW badge, type/routing/channel chips, mark-read via fetch). "Alert
   settings" link (admins), Mark all read, Flush queue.
5. **Scan history** `/scan-history` (152 lines). "Run scan now" (POST
   /hosts/all/scan). 3-cell stat strip computed IN JINJA over the current
   page only (numbers are per-page, not fleet). Batch cards with expandable
   per-host tables (page-local toggleBatch + cw-hidden — a third disclosure
   mechanism). 
6. **Insights** `/insights?tab=calendar|trends` (237 lines). Header contains
   TWO nav systems: role=tablist anchors (Calendar/Trends) + a `|`-separated
   "Reports" link row (Compliance | Readiness | Crypto) — the sole entry to
   three full pages. Calendar: weekly buckets, storm chips, inline-styled flex
   rows. Trends: hand-built stacked bar charts of nested flex divs (28 inline
   styles — highest in codebase). Arrow-key tab JS does full page loads.
7. **Compliance** `/reports/compliance?tag=` (151 lines). Toolbar
   (Refresh/JSON/CSV/Print), report block, stat strip, grade chips, metric
   bars, per-bucket remediation tables, signed footer (SHA-256/HMAC/verify
   cmd). `?tag=` scope has NO UI control. Own `<style>` block (print CSS +
   locals).
8. **Readiness** `/readiness` (248 lines). Milestone timeline, stat strip,
   workload forecast, THREE tables with identical headers copy-pasted. Own
   `<style>` duplicating compliance's print CSS verbatim; redefines
   .cw-section-hdr.
9. **Crypto** `/crypto` (116 lines). Stat strip, 3 mini tables, weak
   primitives table, PQ note. Header says "Informational — does not affect
   grades". Own `<style>`: third .cw-section-hdr + .cw-td-num right-alignment
   that exists nowhere else. No interactivity.
10. **Team** `/team` (138 lines). Dashboard's table minus all controls, with
    a copy-pasted stat_card macro and an email-gated "No team assigned" dead
    end. No search/filter/sort.
11. **Audit** `/audit` (83 lines). The only filter-panel-with-Filter/Clear-
    buttons paradigm in the app. Hand-inlined SVG bypassing the icon macro.
12. **Settings** (settings.html, 1205 lines — largest). 9 sections, TWO URL
    schemes in one nav (`?tab=auth|smtp|alerts|policy|api-keys` vs
    `/settings/alert-groups|events|roles|users`); all nine panels emitted
    every request, hidden by CSS; hidden panels render against empty lists.
    Auth (LDAP test/TOFU pin, OAuth), SMTP (+test), Alerts (webhook presets
    JS, digest, behavior + env badges), Alert groups (create + GET preview
    that round-trips the whole page + per-row `<details>` editors), Policy
    (toggle switches + severity selects + 5-way elif param widgets), Roles
    (create + TWO `<details>` editors per row + IdP mapping subform), Users
    (delete lacks confirm-form — only unconfirmed destructive action in app),
    API keys (one-time token panel). ~230 lines inline JS mixing both dispatch
    conventions.
13. **Events** `/settings/events` (settings_events.html, 76 lines) — a
    settings section that escaped: re-implements settings chrome with its own
    h1 ("Event streaming"), flashes outside the shared panel.
14. **Login** (78 lines) — standalone document (no base.html), TWO structurally
    identical login forms (ids login-username vs login-username-2), OAuth
    button, no-auth fallback.
15. **Setup** (77 lines) — standalone, duplicates login's shell verbatim.

## Cross-cutting

- **Inline styles: 85** total (dashboard 32, insights 28, cert detail 9,
  base 5). `tests/test_no_inline_styles.py` is a per-template ratchet
  ("ONLY GOES DOWN"); its docstring says style-src keeps 'unsafe-inline'
  because of these. Dynamic tones use `style="--tone:{{...}}"` custom-property
  pattern — the reason the budget can't reach zero without a rethink (SVG
  attributes are the way out).
- **tokens.css**: first ~480 lines are a real system; lines ~480-1277 a
  hand-rolled Tailwind subset (cw-mb-14, cw-fz-12-5, cw-w-96,
  cw-text-text-3…). Two toggles (.cw-switch, .cw-toggle), two segmented
  controls (.cw-seg, .cw-segmented), two empty states (.cw-empty,
  .cw-empty-state).
- **JS**: vanilla only, no framework/bundler; AJAX endpoints: /api/health,
  /api/alerts/{id}/read, /api/pivot/*, PATCH /api/hosts/{id}/notes,
  /api/certificates/{id}/revocation, /settings/test-ldap, /settings/pin-ldap-ca,
  /settings/test-smtp. A11y uneven: full ARIA menus/tabs/focus-trap on
  dashboard+insights; zero JS on crypto/readiness/team/audit.
- **Pattern variants**: page wrapper (wrap vs constrained, no rule);
  5 disclosure mechanisms; 3 inline-edit patterns; destructive buttons
  danger-vs-ghost inconsistently; numeric alignment only on /crypto;
  stat markup hand-copied on 5 pages; flash feedback via 5 channels
  (?error, ?saved, context var, async spans, alert()).

## Overlaps

Dashboard↔Team (same data, duplicated macro, fewer features);
cert detail↔host detail (same editors, same endpoint, 2 templates);
host notes editable in 3 places; posture grades shown 4 ways; expiry data
modeled 3 ways; "something is wrong" spread over 4 surfaces; scan triggering
in 5 places; alert routing configured in 4 places; "Reports" means two
unrelated things one click apart.

## Suggested IA (from the exploration; adopted with modifications in brief.md)

Inventory `/` (unified filters; pivots + calendar as groupings; team as saved
filter; trust anchors out) · one degrading asset detail · Posture `/posture`
(crypto + grades + trends; compliance/readiness as generated outputs) ·
Activity `/activity` (alerts + scans + health detail; audit adjacent) ·
Settings (one scheme; absorbs events + trust anchors; routing consolidated).
Cleanups: one of each control; shared macros; print CSS in sheet; explicit
component-init JS instead of the data-action registry; drive inline-style
ratchet to zero and drop 'unsafe-inline'.
